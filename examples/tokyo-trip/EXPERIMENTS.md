# Experiments

Pre-registered tests against reality, append-only. The ledger's value is the
time order: criteria written BEFORE the result exists cannot be bent to fit
it.

### 2026-11-02 — JAL award seats vs. paying cash

**Hypothesis:** JAL releases more award seats for April dates around T-330
days; monitoring at the release window will beat paying ~$1,400 cash now.
**Method:** Check JAL award search for HND, 3 consecutive mornings starting
2026-11-04 (the T-330 window for the Apr 1 outbound).
**Criteria (pre-registered):** Award seat in economy or premium economy by
2026-11-07 = book it, cancel the cash-fare watch. Nothing by 11-07 = the
release-window theory is wrong for this route in cherry-blossom season —
book cash by 11-10 before spring pricing moves, and stop monitoring.
**Result:** RESOLVED 2026-11-05, day 2 — premium economy award appeared
(80k points + $67). Booked.
**What it changed:** Flight line in BOOKINGS.md moved from tentative to
confirmed; freed ~$1,400 in the trip budget (DECISIONS.md 2026-11-05);
release-window monitoring is now the default first move for future JAL
bookings. Note the null was pre-declared as *evidence against the theory
for this season*, not as "keep waiting" — the exit date was set before
the first check.
